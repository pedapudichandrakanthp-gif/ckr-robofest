\# CKR Website — Development Rules



Project:

Chandrakanth Robofest (CKR)



Business:

Premium Robot Entertainment \& Event Experiences



Location:

Anakapalle, Andhra Pradesh, India



\## Core principle



This is a real business website foundation, not a fictional

startup landing page.



The website must be designed so it can become the actual

production booking platform.



\## Design



The visual identity should combine:



\- premium event/wedding aesthetics

\- modern robotics

\- celebration

\- elegance

\- cinematic presentation

\- sophisticated typography

\- premium photography/video

\- subtle festive details



Do NOT use:



\- childish cartoon styling

\- excessive neon

\- cyberpunk aesthetics

\- gaming UI

\- generic AI SaaS appearance

\- excessive glassmorphism

\- literal celebration emojis as design elements



\## Truthfulness



Never fabricate:



\- customers

\- testimonials

\- event photographs

\- revenue

\- bookings

\- robot ownership

\- awards

\- partnerships

\- certifications

\- manufacturer authorization



Demonstration/stock/manufacturer media must never be

presented as CKR-owned event footage.



\## Architecture



Use:



\- Next.js

\- TypeScript

\- Tailwind CSS

\- shadcn/ui

\- Supabase

\- PostgreSQL



\## Code quality



Use strict TypeScript.



Prefer reusable components.



Do not duplicate components unnecessarily.



Do not overwrite working code without first inspecting it.



Do not remove functionality without explicit instruction.



Do not create fake backend functionality.



All future business data should be database-ready.



\## Booking



The system must eventually support:



\- event date

\- start time

\- end time

\- venue

\- customer details

\- robot

\- package

\- add-ons

\- estimated price

\- booking status

\- availability



Prevent double booking.



Include setup/travel/pack-down buffers.



\## Pricing



Pricing must be editable.



Never hard-code pricing throughout multiple components.



\## Robots



Robot capabilities must be represented as configurable data.



Never promise capabilities that the actual robot does not support.



\## Mobile



Mobile-first and fully responsive.



\## SEO



Use proper metadata, semantic HTML,

structured content and accessible navigation.



\## Safety



Robot event operations must not encourage unsafe

guest interaction.



\## AI development behavior



Before modifying the project:



1\. Inspect the existing project.

2\. Understand the architecture.

3\. Identify dependencies.

4\. Make the smallest appropriate change.

5\. Run tests/build/lint where available.

6\. Report what changed.



Never claim something was tested if it wasn't.
